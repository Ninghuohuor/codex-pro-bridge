# ADR 0002: 全局 MCP 与任务内项目绑定

日期：2026-09-25。状态：采用。

最初的逐项目 `setup` 要求用户在每个 Codex 项目开始前安装一次。用户明确要求在任选本地项目新建任务后即可使用 Bridge，不先向开发者报出项目名称。因此改为一次性安装全局 MCP，使用 `serve --auto` 启动。Skill 从当前 Codex 工作区确定准确根目录，首次需要 Bridge 时调用 `codex_pro_bind_project`；运行器本地注册或复用该项目，并返回项目编号。绑定不读取文件正文，也不向 ChatGPT 发送内容。同一 MCP 连接不能切换到其他项目，后续工具必须携带绑定编号。

全局入口只消除了逐项目安装。项目文件仍由 Codex 在当前任务范围内明确选择；快照、秘密扫描、任务去重、账户与 Pro 选项核对、发送意图和有限外发授权继续生效。无授权时任务等待批准，不因自动绑定而自动外发。`setup --root` 留作项目专用的兼容入口。

本机测试：两个新项目由不同 MCP 连接绑定，拒绝跨项目调用和同连接改绑；从已配置项目和未预配置的示例项目都能看到全局 `serve --auto`，并完成真实全局 MCP 绑定与状态读取。尚未证明 Codex 在每一种自然语言任务中都一定隐式选用 Skill；普通小任务本来也不要求调用。Windows Server 2022 CI 和 Windows 11 原生验收另行记录。
