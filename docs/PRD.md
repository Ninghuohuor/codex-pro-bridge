# Codex Pro Bridge — 产品需求

## 1. 产品定义与名称

### 1.1 一句话定位

**让本地 Codex 通过 MCP，向用户已登录的 ChatGPT 网页端 Pro 发起咨询，并把对应回答带回当前开发任务。**

中文说明：Codex 与 ChatGPT 网页端 Pro 的非官方协作桥。

这里的 Pro 指用户希望选择的网页能力，不是由本软件新增的账户权限。目标页面可能将其展示为模型选项、推理档位或其他组合；软件必须依据实测页面配置，不假定后台模型 ID。

### 1.2 统一命名

| 位置 | V0 命名 |
|---|---|
| 产品名称 | Codex Pro Bridge |
| 建议仓库名 | `codex-pro-bridge` |
| 拟定 CLI 命令 | `codex-pro-bridge` |
| MCP Server 标识 | `codex-pro-bridge` |
| MCP 工具前缀 | `codex_pro_` |
| 可选 Skill 名称 | `codex-pro-bridge` |
| 产品文档 | `docs/PRD.md` |
| 技术文档 | `docs/TECH_SPEC.md` |

仓库名、包名和品牌均为拟定名称，尚未据此确认可注册、无冲突或满足所有品牌使用规则。不要冒充官方项目，不使用暗示官方背书的标识。公开发布前单独完成包名、许可与品牌核验。

### 1.3 各部分只承担一种职责

| 部分 | 负责 | 不负责 |
|---|---|---|
| Codex | 理解需求、选择上下文、修改本地代码、运行测试、核验建议 | 不把网页回答直接当作必须执行的命令 |
| 网页 ChatGPT Pro | 方案、分析、代码审查、调试建议 | 本方案不赋予它本地写文件或执行终端的能力 |
| MCP 软件 | 发送、状态跟踪、提取、隔离、恢复、留存必要证据 | 不替换 Codex 主模型，不提供模型推理服务 |
| 可选 Skill | 说明什么时候咨询、如何规划与审查 | 不是连接网页的运行时，不是必装前提 |

### 1.4 费用与权限表述

本软件的网页咨询路径不接 OpenAI 模型 API，不要求用户为桥接配置模型 API Key。Codex 自己的主模型、登录方式及计费路径保持不变；接入一个 MCP 并不会让 Codex 的推理免费。官方区分 Codex 的订阅登录与 API Key 使用路径。[O2]

因此只可以说“网页咨询路径无需另接模型 API”，不能说“整个 Codex 免费”“无限 Pro”“把网页额度转成 Codex 额度”。网页账户能否选择 Pro、剩余额度、实际限制以用户页面和适用规则为准，本软件不扩权、不伪造额度。

## 2. V0 要解决的问题

当前操作需要人为整理文件、复制到网页、等待回答、再搬回 Codex，容易遗漏上下文或混淆任务。V0 优先解决搬运与可追踪性，不以“自动化后模型一定更聪明”为前提。

首批用户是项目作者本人，以及同样使用本地 Codex、拥有可用 ChatGPT 网页账户的开发者。先证明自己每天能用，再决定公开推广。

### 产品目标

用户在 Codex 中一句话发起咨询；外发内容有明确范围；网页回答能与本次请求准确对应；长任务超时不丢失记录；失败原因可理解、可处理；安装和卸载不破坏原有 Codex 设置。

### 明确不做

V0 不做模型供应商/API 中转，不替换 Codex 的所有推理；不做账号池、共享登录、付费代调用或额度绕过；不做云端 SaaS、远程代码 Tunnel、自动管理 ChatGPT Projects、全历史同步、所有浏览器和所有客户端适配；不做网页回答直接运行命令的执行器。

**V0 是完整的一条链路，不是完整的所有功能。**

## 3. 首版范围

| 编号 | 必须交付的能力 | 验收边界 |
|---|---|---|
| F01 | 本地 stdio MCP | Codex 能列出五个工具并调用，不依赖 Skill |
| F02 | 一体化 setup / doctor | 检查环境、预览配置变更、定位故障 |
| F03 | 专用浏览器登录 | 用户手动登录，保留该专用 Profile |
| F04 | 网页 Pro 选项检查 | 发送前后检查可见选项，不做后台模型身份承诺 |
| F05 | 文本咨询 | ask / plan / review / debug 共用一套发送引擎 |
| F06 | 上下文准备 | 明确文件或片段、限定 diff、文本日志；不全仓上传 |
| F07 | 外发授权 | 逐任务确认，或用户主动开启的限时限量授权 |
| F08 | 长任务 | 提交快速返回任务号，后续读取状态和结果 |
| F09 | 对话连续性 | 本工具创建的对话可继续追问，按项目隔离 |
| F10 | 失败恢复 | 区分未发送、可能已发送和已确认发送；不盲重发 |
| F11 | 取消与限额停止 | 取消本地排队，尽力停止上游；限额时暂停 |
| F12 | 结果与留存 | Markdown、分页、调用记录、保留期与清理 |

首版不实现图片/PDF/仓库压缩包上传，不解析 Canvas、生成文件和音视频，不自动导入任意历史对话。返回包含这些内容时明确标记“该部分未捕获”，而非声称完整支持。

可选 Skill 随包提供，安装时由用户选择启用。它不增加第六个 MCP 工具。

## 4. 用户体验

### 4.1 第一次使用

用户运行 setup，选择本地仓库。程序检查 Node、浏览器、Codex 和当前项目，展示将新增的 MCP 配置。用户确认后打开专用浏览器，自己完成登录，并确认要使用的网页选项。

setup 不读取用户日常浏览器的登录数据，不代输密码或验证码，不修改 Codex 主模型/API 设置。安装成功与网页登录成功分别显示，不能混成一个绿色“全部可用”。

### 4.2 日常咨询示例

用户在 Codex 中说：

> 用网页高推理模式审查示例项目的任务经验值改动，先指出风险，不要直接改代码。

预期过程：Codex 选择相关文件 → MCP 准备快照 → 用户确认外发或命中已有授权 → 创建网页任务 → 等待并取回回答 → Codex 说明哪些建议已经核验、哪些仍需验证。

用户看到的是任务进展，而不是几十次点击工具调用。软件不得输出“Pro 已审查真实代码”，除非本次选中的代码确实已被发送且对应答复已成功取回。

### 4.3 后续追问

“继续让它分析第二个风险”使用上一次返回的 `session_id`。不能通过“当前激活的 ChatGPT 标签页”猜测目标对话。新的独立任务默认新对话，不永久共用一个项目长线程。

### 4.4 失败提示必须具体

| 场景 | 提示含义 |
|---|---|
| 尚未登录 | 尚未发送。请在专用浏览器完成登录后恢复任务 |
| Pro 选项不可用 | 尚未发送。不会自动选择其他档位 |
| 已发出但未拿到结果 | 原请求可能仍在处理；先查询原任务，不重复提交 |
| 页面状态不认识 | 停止网页动作，等待适配或人工检查 |
| 用户修改了草稿/切了对话 | 检测到人工操作冲突，不覆盖、不猜测 |
| 发现限额或验证页面 | 暂停后续发送，需要用户处理，不自动绕过 |
